## 1. 数据

| 项 | 值 |
|---|---|
| 来源 | THUCTC 官方 `THUCNews.zip`（1,560,309,796 字节，HTTP Range 校验） |
| 实际篇数 | **834,958**（官方宣称 74 万；zip 内另有 83 万个 `__MACOSX` 垃圾成员，已剔除） |
| 类别 | 14 类；头部**科技 162,818**，尾部**星座 3,576**，**长尾比 45.5×** |
| 文本长度 | 平均 **937 字**；标题均值 18.9 字，98.3% 的样本能拆出标题 |
| 去重 | 正文 md5 精确去重，剔除 1,116 条（0.13%） |

**切分**（seed=42，互不重叠）：

| 集合 | 规模 | 用途 |
|---|---|---|
| `train_100k` | 99,993 | 主训练集（按自然分布） |
| `sub_1k/5k/10k/20k/30k/50k` | 嵌套子集 | 数据量曲线、超参消融 |
| `val_10k` | 9,993 | 早停 / 选超参 |
| `test_nat_10k` | 9,993 | acc（贴近线上分布） |
| `test_bal` | 4,200 | **macro-F1 主指标**（每类 300 条） |

**为什么两个测试集**：按比例抽 10k 时"星座"只有 42 条，其 F1 的 95%CI 半宽超过 ±10pp，
任何"这个类提升了"的结论都不可信；而按比例算 acc 才贴近真实部署。
所以主指标在 `test_bal` 上算、辅助指标在 `test_nat_10k` 上算，两者分开汇报。

### 1.1 长度：本项目最容易被忽略的事实

| max_len | 完整保留的样本 | 平均丢弃 |
|---|---|---|
| 128 | 5.4% | 721 token（85.1%） |
| **256** | **15.6%** | **606 token（71.6%）** |
| 384 | 27.6% | 506 token（59.8%） |
| 512 | 39.2% | 421 token（49.7%） |

新闻正文平均 937 字，中文几乎 1 字 = 1 token。**任何"截断到 256 就够"的说法都需要被这张表检验。**
因此输入构造统一采用 `head_tail`（标题 + 前 60% + 后 40%），而不是纯 head。

## 2. 实验口径（对比能成立的前提）

- **同一批样本**：所有方法在 `test_bal` 与 `test_nat_10k` 上评测，样本 id 来自 `all.jsonl` 的全局行号。
- **同一个指标函数**：`common/metrics.py`，生成式的拒答/解析失败**计入分母**（算错），失败率单列。
- **同一个截断实现**：`common/text.py`，三条方法线共用（否则 max_len 消融比的是两种输入构造）。
- **固定 seed=42**，`cudnn.deterministic=True`。
- **配对检验**：`eval/paired_test.py`（McNemar 精确二项检验），不拿小数点当结论。

| **BERT-base 微调** 100k×3ep | `t1__bert__bert-base-l256-100k-3ep` | **0.9628** | **0.9701** | 0.9731 | 0 | 0.027 | 51.5 min | 4.5 GB |

| Qwen2-0.5B zero-shot | `t1__llm-local__qwen2-0shot` | 0.5437 | 0.5274 | 0.7264 | **20.4%** | N/A | 7.4 min | 1.5 GB |

**配对检验（McNemar，同一批 4200 条，`test_bal`）**：

| 对比 | 差值 | p 值 | 结论 |
|---|---|---|---|
| BERT vs TF-IDF-SVM | +3.98pp | <0.0001 | 高度显著，微调确实有效 |
| TF-IDF-SVM vs LoRA | +11.45pp | <0.0001 | 高度显著，**5 分钟 CPU 打败 57 分钟 GPU** |
| LoRA vs Qwen zero-shot | +28.12pp | <0.0001 | 高度显著，SFT 修好了"标签空间不闭合" |
| Qwen zero-shot vs 关键词规则 | +0.64pp | **0.514** | **不可分辨**：0.5B 零样本 ≡ 关键词，但贵两个数量级 |
| TF-IDF LR vs SVM | −0.71pp | 0.0002 | 显著，SVM 更好（但没概率） |

**读法**：`macro-F1` 看各类是否均衡，`acc` 看真实分布下的整体正确率，两者差得越多说明模型越偏向头部大类。

## 4. 逐层解读

### L0 规则 / 关键词（macro-F1 0.539）

14 类 × 10~15 个强关键词，标题权重 ×2。它证明了两件事：
1. 新闻类别的**头部信号非常强**（"涨停"→股票、"中超"→体育），一半样本靠词表就能分对；
2. 但它也是**校准最差**的方法：ECE 0.239，意味着"高置信错误"大量存在——
   这正是后续做置信度闸门时必须用模型概率、而不是规则命中的原因。

### L1 TF-IDF（macro-F1 0.914~0.924）

| 配置 | macro-F1 | acc | 拟合耗时 | ECE |
|---|---|---|---|---|
| char_wb(1,3) + LinearSVC | **0.9237** | **0.9491** | 63s | N/A（无概率） |
| char_wb(1,3) + LR | 0.9166 | 0.9459 | 171s | 0.018 |
| jieba 分词 + LR | 0.9144 | 0.9419 | 103s | 0.022 |

三个结论：
- **字 n-gram 优于分词**（+0.2~0.9pp）。中文新闻里的实体（"双色球""沪指"）在分词器眼里会被切碎，
  字 1-3 gram 反而更稳，且不需要额外依赖；
- LinearSVC 比 LR 高 0.7pp 且快 2.7 倍，**代价是没有概率**——所以它不能用于置信度路由；
- TF-IDF 的 ECE 只有 0.018，比 BERT 的 0.027 还低。**"深度模型概率更准"是错觉**，
  LR 在高维稀疏特征上天然校准得好。

### L2 BERT 微调（macro-F1 0.9628）

| 指标 | 值 |
|---|---|
| val macro-F1 | 0.9659（ep3，仍在缓升，未见明显过拟合） |
| test_bal macro-F1 | **0.9628** |
| test_nat acc | **0.9701** |
| 主题层 F1（14→6 组） | 0.9767 |
| ECE | 0.0268 |
| 单 epoch | 1030s（17.2 min，含 10k val 评估） |
| 显存峰值 | 4.53 GB |
| 推理 | 2.7 ms/条（bs=32 摊薄后） |

相对 TF-IDF 的 **+3.9pp**（0.9237→0.9628）是这次实验里最大的一次跃升，
但它花掉了 55 分钟 GPU 时间，而 TF-IDF 只要 5 分钟 CPU。**这个交换是否值得，取决于你要那 4 个点做什么。**

- 训练曲线 `train_loss 0.248 → 0.086 → 0.043`，`val_loss 0.126 → 0.130 → 0.136`：
  第 2 个 epoch 起 val_loss 已开始回升，**最优轮数其实是 2~3，再加 epoch 只会过拟合**；
- 最差类别是**科技**（F1 0.923，精确率仅 0.889）：它把大量"财经/游戏"新闻吸过来，
  因为科技新闻里也大量出现"公司/发布/产品"这类词；
- 主要混淆对：财经→股票 14 条、彩票→体育 10 条、游戏→科技 9 条。
  **财经/股票的混淆是标注体系本身的问题**（宏观财经与个股行情边界模糊），不是模型能力问题。

### L3 本地小模型 zero-shot（Qwen2-0.5B-Instruct）

| 指标 | 值 |
|---|---|
| macro-F1（`test_bal`） | **0.5437** |
| acc（`test_bal`，全样本计入分母） | 0.5271 |
| acc（`test_nat_10k`） | 0.5274 |
| **拒答率** | **20.4%**（`test_bal` 855/4200） |
| 若只算解析成功 | acc 0.662 → **虚高 13.5pp** |

两个必须讲清楚的现象：

1. **它和关键词规则打平（0.539 vs 0.544），但成本高出两个数量级。**
   0.5B 模型的通用语义能力无法弥补"没在这个标签体系上训练过"这件事。

2. **拒答不是格式问题，是"标签空间不闭合"问题。** 抽检 855 条拒答：
   模型输出的是 `足球`（而不是 `体育`）、`NBA`、`美股` 这类**语义正确但不在 14 类白名单里**的词。
   集中在时政（184）、星座（137）、房产（119）——恰好是标题里大量出现专有名词/口语表达的类。
   这解释了为什么"只算解析成功"的 acc 会虚高 13.5pp：**被丢掉的样本并不是随机丢的，而是难度更高的那一批。**

> 这也是 L4（LoRA）存在的理由：不是"让模型更聪明"，而是**让它学会只输出这 14 个词**。

### L4 LoRA SFT（Qwen2-0.5B，10k×3ep，可训练 1.08M / 0.218%）

| 指标 | 值 |
|---|---|
| macro-F1（`test_bal`） | **0.8104** |
| acc（`test_bal`） | 0.8083 |
| acc（`test_nat_10k`） | 0.8578 |
| **拒答率** | **0.6%**（zero-shot 是 20.4%） |
| 训练曲线 | train 0.139 → 0.049 → 0.025；**val 0.077 → 0.051 → 0.064** |
| 单 epoch | 994s / 1174s / 1223s（逐轮变慢，见下） |
| 显存峰值 | 4.60 GB |

三个结论：

1. **SFT 的主要收益不是"更聪明"，而是"学会闭嘴"。** 拒答率 20.4% → 0.6%，
   准确率 0.527 → 0.808（+28.1pp，p<0.0001）。零样本那 855 条拒答里大量是
   `足球`/`NBA`/`美股` 这种"语义对、不在白名单"的输出，微调后模型被强制收敛到 14 个词上。
2. **第 3 个 epoch 开始过拟合。** val_loss 0.051 → 0.064 回升，而 train_loss 还在降
   （0.049 → 0.025）。**最优轮数是 2**，多训的那一轮是在记噪声。
3. **它仍然输给 TF-IDF 11.5pp、输给 BERT 15.2pp。** 0.5B 的容量 + 只训 10k 条，
   在"封闭标签 + 长文本"的任务上不具备竞争力。它的真正价值是**验证了生成式路线可行**，
   以及在"必须输出结构化结果"的场景下作为可控 pipeline 的一环。

> 工程细节：三个 epoch 的耗时是 994s → 1174s → 1223s，逐轮变慢 23%。
> 这不是数据问题，是**笔记本持续满载后的热降频**（GPU 温度稳定在 77~79°C，
> 功耗从 84W 掉到 72W）。做长训练排期时要把这个 20% 的衰减算进去。

## 6. 工程结论（比指标更值得带走）

1. **显存过 7GB 不是 OOM，是静默降级。** bs=64/L=256 峰值 7.24GB，吞吐从 121 掉到 36 samples/s；
   LoRA bs=8 峰值 8.75GB 甚至"成功"了（溢到 WDDM 共享内存）。所有训练脚本都带
   `max_memory_allocated < 6.5GB` 断言，越线直接报错。
2. **`.half()` + GradScaler 是错的**（`unscale FP16 gradients`）。正确做法是权重 fp32 + autocast，
   或者直接 bf16（实测 117 vs 121 samples/s，几乎无损且不用 scaler）。
3. **tokenize 缓存必须带数据指纹。** 缓存键只写 split 名时，重新生成切分后会静默命中旧缓存——
   我第一次的"100k 训练"实际只训了 1200 条，val 卡在 0.44。
4. **74 万 txt 不要解压。** 直接流式读 zip 转单 jsonl，55 秒完成；解压要写 1.8GB 且 NTFS 遍历极慢。
5. **DeepSeek-V4.1-Flash 默认是推理模型**，不显式 `thinking: disabled` 时 `max_tokens=8` 拿不到答案。

## 7. 局限与下一步

**本轮实际跑完的**（7 个 run，全部在 `test_bal` 4200 条上配对可比）：
规则、TF-IDF×3（字/词 × LR/SVM）、BERT-base 100k×3ep、Qwen2-0.5B 零样本、LoRA 10k×3ep。
主要结论都已经有配对检验支撑。

**还没跑的**（清单在 `scripts/10_run_queue.py`，`--list` 可看预算）：

- **主干对比**（roberta-wwm / macbert @30k×2ep，各约 12 min）：权重已下好，只差跑。
  注意必须同时跑 `bert-base @30k`（12 min）作为同规模分母，否则"换主干涨了"会被质疑不公平。
- **max_len 消融**（128/384/512，6/18/26 min）：**这是本项目最该补的一项**。
  既然 256 只完整覆盖 15.6% 的样本，384 很可能还有 1~2pp，代价是每 epoch 从 17 分钟涨到 22/53 分钟。
- **class_weight balanced**（12 min）：长尾类（星座 3576 条/占 0.43%）的 F1 明显偏低，
  需要验证"加权能不能救 macro-F1、会不会牺牲 acc"。
- **数据量曲线**（5k/20k/50k，4/10/24 min）：回答"这任务需要多少数据"。
- **LoRA 的 rank / 数据量 / target_modules 消融**、**DeepSeek API 全量对比**（成本约 1~3 元）。

**已知的口径局限**：

- 单次运行（seed=42），没有跑 seed 43/44 报方差。BERT 与 TF-IDF 差 3.9pp 已足够显著，
  但 Tier-2 那些 0.3~0.7pp 的差异**必须**先看 `eval/paired_test.py` 的 p 值。
- 标题/正文是按首行启发式拆的（98.3% 命中），不是官方字段。
- DeepSeek 只做了连通性与成本验证（40 条 / 0.01 元 / 0 解析失败），未跑完整对比。
